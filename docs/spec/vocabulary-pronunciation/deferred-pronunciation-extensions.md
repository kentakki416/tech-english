## 対象範囲

| | MVP | 着手後 |
| --- | --- | --- |
| 単語帳のカードの発音・1 文 | ✅ | ✅（変わらない） |
| 解答画面・結果画面の単語のカード | ❌ | 単語のカードに発音のボタン |
| 英和辞書の全見出し語の音声 | ❌（単語帳に出うる語句だけ） | 約 4.7 万語をまとめて作る |
| 読み方の調整 | ❌ | Polly の Lexicon で読み方を指定 |
| admin の画面 | ❌（SQL で戻す） | 失敗の一覧・再試行・作り直し |
| 速度・声 | 1 倍・1 種類 | 読み上げと同じ選択肢 |

## 解答画面・結果画面の単語のカードの発音

- 解答画面で単語をタップしたときの単語のカード（[reading-practice](../reading-practice/README.md)）に、発音のボタンを置く
- 単語のカードは調べたその場で出るので、「調べてから最大 1 時間で作る」では間に合わない。**英和辞書の全見出し語（2026 年 10 月時点で 46,612 語、平均 9 文字）の音声を先に作っておく**
  - 費用：約 42 万文字 × $16 / 100 万文字 = **約 $6.7（1 度だけ）**。保存は 1 語 約 8KB で約 370MB（月 約 $0.01）
  - `generate:word-audio` の候補に「英和辞書の見出し語」を最後の優先で足す。1 回 300 語なら 1 時間ごとで約 6.5 日かかるので、着手時だけ `WORD_AUDIO_MAX_PER_RUN` を上げるか手動で何度か実行する。月の上限（`AUDIO_MONTHLY_CHARACTER_LIMIT`）に余裕があることを確かめる
- 用語集の語句は公開から最大 1 時間で作るので、問題が公開された直後に解く人だけ「準備中」になる（許容する）
- 解答中の発音をアシストに数えるか（数えるなら `reading_attempts` に列を足す。読み上げとは別の列）を決める

## 略語・技術用語の読み方の調整

- Polly の Lexicon（発音辞書）か SSML の `<sub alias="A P I">api</sub>` で読み方を指定する。SSML のタグは課金文字数に入らない
- 読み方の辞書は admin で管理する。辞書を変えたら、その語の音声を作り直す（`text_hash` に辞書の版を含めてキーを変える）
- 単語の音声は見出し語（小文字）から作るので、大文字の表記（`API`）を残したいなら、用語集の本文中の表記から作る案もある（語句ごとに表記がぶれるので、辞書で指定する方がよい）

## 単語の音声の admin の画面

- admin に単語の音声の一覧（状態で絞り込み）を足し、`failed` の語の「再試行」と、`ready` の語の「作り直す」を置く
- 作り直しは、読み上げと同じく前の音声を出しながら別のキーで作る（`passage_audios.regenerate_requested_at` と同じ列を `word_audios` に足す）

## 速度の切り替え・声の選択

- 声の選択は、読み上げの声の選択に合わせて `word_audios` を「1 語 1 行」から「1 語 × 声 1 行」にする（unique を `(lemma, voice_id)` に変える）
- 速度は再生側（`playbackRate` / `setPlaybackRate`）だけで変えられるので、音声を作り直す必要は無い

## 既存仕様との差分（着手時のチェックリスト）

- [ ] 解答画面の単語のカード：`GET /api/attempt/:id` か単語のカードの取得に単語の音声の URL を足す。web・mobile の単語のカードにボタン
- [ ] 英和辞書の全見出し語：`generate:word-audio` の候補の順と、着手時の作り置きの手順（`WORD_AUDIO_MAX_PER_RUN`・月の上限）
- [ ] 読み方の調整：`word_audios.text_hash` に辞書の版を含める。読み上げのテキストの作り方（`buildSpeechText`）と同じ辞書を使う
- [ ] admin の画面：`word_audios` に `regenerate_requested_at`、admin の API と画面
- [ ] 声の選択：`word_audios` の unique 制約、api が返す URL の選び方
