## サーバーからのプッシュ通知

### 着手トリガー

- 「今日もう解いたのに通知が来る」という不満が目立つ
- 連続学習日数が途切れそうなとき（例：21 時時点で今日まだ学習していない）にだけ送りたい
- 通知の文言に連続日数などの最新の情報を入れたい

### 対象範囲

| | MVP（ローカル通知） | 着手後（プッシュ通知） |
| --- | --- | --- |
| 通知を出す主体 | 端末の OS（予約） | サーバー → Expo Push Service → APNs / FCM |
| 今日学習済みなら送らない | ❌ | ✅ |
| 文言に最新の情報 | ❌ | ✅ |
| 時刻の基準 | 端末の時刻 | `users.timezone` |
| サーバー側 | 設定の保存のみ | 端末トークンの管理、送信ジョブ、送信結果の処理 |

### 設計案

- 端末トークン：ログイン時に `expo-notifications` で Expo Push Token を取得し、`POST /api/user/push-device` で登録する（`push_devices`：`user_id`、`token`、`platform`、`last_seen_at`）。ログアウト時に削除する
- 送信ジョブ：cron `send:reminders` を 15 分ごとに起動する。`reminder_settings` から「`users.timezone` での現在時刻が設定時刻の 15 分枠に入る」ユーザーを選び、`study_date = 今日` の挑戦があるユーザーを除いて送る
- 送信は `expo-server-sdk` で 100 件ずつまとめて送る。送信結果（receipt）で `DeviceNotRegistered` が返ったトークンは削除する
- 冪等：`reminder_deliveries (user_id, local_date)` に unique 制約をかけ、同じ日に二重に送らない（ジョブの再実行・重複起動に備える）
- 移行：API が「プッシュ通知に移行済み」を返したら、app はローカル通知の予約をすべて取り消す

### 既存仕様との差分（着手時のチェックリスト）

- [ ] **時刻の意味が「端末の時刻」から「`users.timezone` の時刻」に変わる**。設定画面の表記と、既存の設定値の扱いを決める
- [ ] APNs のキーと FCM の設定、EAS の push 資格情報を用意する
- [ ] [minimal-deploy](../minimal-deploy/README.md) で、15 分ごとの ECS RunTask（1 日 96 回）の費用と起動時間を見積もる。重ければ送信ジョブだけ Lambda にする
- [ ] `push_devices` / `reminder_deliveries` のテーブルを追加する
- [ ] app のローカル通知の予約を取り消す移行処理を入れる

## web のリマインダー

### 着手トリガー

- web だけを使うユーザーが多く、継続率が mobile より低い

### 設計案

| 手段 | 長所 | 短所 |
| --- | --- | --- |
| メール | 確実に届く。GitHub のメールアドレスが既にある（`users.email`） | 埋もれやすい。送信基盤（SES 等）と配信停止の仕組みが必要 |
| Web Push | 目に付きやすい | iOS はホーム画面に追加した場合しか届かない。Service Worker と VAPID 鍵の管理が必要 |

どちらもサーバーからの送信になるため、**サーバーからのプッシュ通知の送信ジョブを先に作り、送信先の種類として追加する** 形にする。
