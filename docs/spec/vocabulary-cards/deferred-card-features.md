## 着手トリガー

| 機能 | トリガー |
| --- | --- |
| 単語の一覧 | 「覚えた単語を見返したい」「知っている単語を出さないでほしい」という要望が出た |
| 同じ回の中での繰り返し | 「まだ」の割合が高く、翌日まで待つと忘れたままになっている（ふりかえりの後にすぐ閉じられている）ことが分かった |
| 先取りの復習 | 今日の分を終えた後に、続けてめくりたいという要望が出た |
| 単語の発音 | 読み上げ（[read-aloud](../read-aloud/README.md)）の利用が多く、単語ごとの発音の要望が出た（[read-aloud の deferred](../read-aloud/deferred-voices-and-pronunciation.md) と合わせて検討） |
| 1 日の新しい単語の上限 | 新しい単語を一度に入れすぎて、数日後の今日の復習が数十枚に膨らむユーザーが目立った |

## 対象範囲

| | MVP | 着手後 |
| --- | --- | --- |
| カードをめくって覚えた / まだを付ける | ✅ | ✅（変わらない） |
| 単語の一覧・カードを外す | ❌ | 段階ごとの一覧と、出題から外す操作 |
| 同じ回の中での繰り返し | ❌ | 「まだ」のカードを回の最後にもう一度出す |
| 先取りの復習 | ❌ | 今日の分が無いときに、次に出す日が近い順にめくれる |
| 単語の発音 | ❌ | カードの語句を読み上げる |
| 1 日の新しい単語の上限 | ❌ | 1 日に入れる新しい単語の数を設定できる |

## 単語の一覧

- 単語帳のトップから開く。段階で絞り込み（復習中 / 覚えた単語）、見出し語・意味・次に出す日を並べる
- **カードを外す**：「知っているので出さない」を選ぶと、段階 4（覚えた単語）と同じく出題しない。外したことが分かるよう、`vocabulary_cards` に `is_excluded`（boolean）を足す案と、段階 4 にそろえる案がある。覚えた単語の数に混ぜたくないなら前者
- 新しい単語も外せるようにするなら、外した時点で `vocabulary_cards` の行を作る（今は初めて答えたときに作る）

## 同じ回の中での繰り返し

- 「まだ」を押したカードを、その回の最後にもう一度出す。2 回目の答えは保存しない（翌日に出すことは変わらない）か、2 回目に「覚えた」なら段階 0 のまま翌日に出す、のどちらかを決める
- 1 回の枚数が最大 20 枚まで伸びるので、1〜2 分の目安が崩れないかを確かめる

## 先取りの復習

- 今日の分が無いとき、トップに「先取りで復習する」を出す。`due_date` が近い順に 10 枚
- 先取りで「覚えた」を付けたときの間隔は、答えた日から数える（今と同じ）。間隔が実質的に短くなるため、先取りでは段階を進めない案も検討する

## 単語の発音

- カードの語句を Amazon Polly で読み上げる。単語ごとに音声を作るか、カードを出すときに都度作るかで費用が変わる（[read-aloud の費用の見積もり](../read-aloud/README.md) を参照）
- 見出し語の音声を `lemma` 単位でキャッシュすれば、ユーザーをまたいで使い回せる

## 1 日の新しい単語の上限

- 設定画面に「1 日に入れる新しい単語の数」（既定は無制限か 20）を足す
- 今日入れた新しい単語の数は、今日の `vocabulary_reviews` のうち `stage_before IS NULL` の行を数えれば分かる（テーブルの追加は要らない）

## 既存仕様との差分（着手時のチェックリスト）

- [ ] 単語の一覧：`GET /api/vocabulary/cards`（cursor ページング）を足す。外す操作を足すなら `vocabulary_cards` の列と `GET /api/vocabulary/session` の除外条件を変える
- [ ] 同じ回の中での繰り返し：2 回目の答えを保存するかを決め、保存するなら `vocabulary_reviews` に回の識別子を足す
- [ ] 先取りの復習：`GET /api/vocabulary/session` に先取りのモードを足す
- [ ] 1 日の新しい単語の上限：設定の保存先（`user_goals` に列を足すか、新しいテーブルか）を決める
- [ ] mobile と web の両方の画面を `design-mock` で決める
