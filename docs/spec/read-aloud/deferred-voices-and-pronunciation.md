## 声の選択

### 着手トリガー

- 「英国英語で聞きたい」「男性の声がよい」という要望が続いたとき

### 対象範囲

| 項目 | MVP | 将来 |
| --- | --- | --- |
| 声 | 1 種類（`Joanna`、en-US） | 2〜4 種類（例：en-US の男女、en-GB の男女） |
| 選ぶ場所 | ― | 設定画面と、再生速度のメニュー |

### 設計案

- `passage_audios` を「1 問 1 行」から「1 問 × 声 1 行」にする（unique を `(passage_id, voice_id)` に変える）
- 費用は声の数に比例する（1 問あたり約 $0.077 × 声の数）。全問ではなく、よく解かれる問題だけ追加の声を作る選択肢もある
- ユーザーの選んだ声は `users` か新しい設定テーブルに持つ

### 既存仕様との差分（着手時のチェックリスト）

- [ ] `passage_audios` の unique 制約と、生成タスクの取得条件（声ごと）
- [ ] `GET /api/attempt/:id/audio` に声の指定を足す
- [ ] 設定画面（web・mobile）に声の選択
- [ ] 費用の見積もりと `AUDIO_MAX_PASSAGES_PER_RUN` の見直し

## 単語ごとの発音

単語帳のカードの発音は [vocabulary-pronunciation](../vocabulary-pronunciation/README.md) で設計した（見出し語ごとに作り置き）。解答画面の単語のカードの発音は、その spec の [deferred](../vocabulary-pronunciation/deferred-pronunciation-extensions.md#解答画面結果画面の単語のカードの発音) で、英和辞書の全見出し語の音声を作る案として続きを検討する。下の設計案（段落の音声から区間を切り出す）は、単語帳の 1 文の読み上げで使った。

### 着手トリガー

- 単語のカードを開いたユーザーのうち、読み上げも使う割合が高いとき（発音を確かめたい需要がある）

### 設計案

- 単語のカードに「発音を聞く」ボタンを置き、**本文の段落の音声から、その単語の区間だけを再生する**（マニフェストの単語の時刻を使う。追加の音声合成は要らないので費用はかからない）
- 単語の前後が切れて聞こえないよう、区間の前後に 50ms ほど余白を取る
- 辞書の単語（本文の外）の発音は、別に音声を作る必要があるので対象外にする

### 既存仕様との差分（着手時のチェックリスト）

- [ ] 単語のカード（web・mobile）にボタン
- [ ] 単語の発音をアシストに数えるか（数えるなら新しい列）

## ユーザーの音読の評価

### 着手トリガー

- 読み上げのシャドーイングの利用が定着し、「自分の発音を確かめたい」という要望が出たとき

### 対象範囲

| 項目 | 内容 |
| --- | --- |
| 録音 | 段落ごとに、ユーザーが英文を声に出して読んだものを録音する |
| 評価 | 発音の正確さ・流暢さ・読み飛ばしを点数にし、うまく読めなかった単語に印を付ける |

### 設計案

- 発音の評価は Azure AI Speech の Pronunciation Assessment が候補（読むべき英文を渡すと、単語ごとの正確さを返す）。2026 年時点で音声 1 時間あたり約 $1.32（リアルタイム）。1 段落 30 秒なら 1 回あたり約 $0.011
- **費用がユーザーの利用量に比例する**（読み上げの音声と違い、作り置きできない）。1 日 10 分使うユーザーで 1 人あたり月 $6〜7 になるため、課金プラン（product-overview の「課金・プラン」）と合わせて検討する
- 録音は端末で行い、評価が終わったら音声は保存しない（個人の音声を持たない）

### 既存仕様との差分（着手時のチェックリスト）

- [ ] Azure の契約・認証情報の管理（新しい外部サービス）
- [ ] マイクの権限（web・mobile）とプライバシーポリシーの更新
- [ ] 1 ユーザーあたりの利用上限（費用の上限）
- [ ] 評価結果を学習記録に残すか

## インラインコードの読み方

### 着手トリガー

- 「`useEffect` の読み方がおかしい」といった指摘が続いたとき

### 設計案

- Polly の Lexicon（発音辞書）か SSML の `<sub alias="use effect">useEffect</sub>` で読み方を指定する
- 読み方の辞書は admin で管理し、変更したら該当する問題の音声を作り直す（本文のハッシュに辞書の版を含める）
- SSML のタグは Polly の課金文字数に入らない

### 既存仕様との差分（着手時のチェックリスト）

- [ ] 読み上げ用テキストの作成（SSML にする）と、文字位置の対応の作り直し
- [ ] admin に読み方の辞書の画面

## バックグラウンド再生

### 着手トリガー

- 結果画面で「本文を聞き流したい」という要望が出たとき

### 設計案

- 結果画面に限り、mobile のバックグラウンド再生（iOS の `UIBackgroundModes: audio`、`expo-audio` の設定）を有効にし、ロック画面の再生コントロールを出す
- 解答中はタイマーと合わせるため、今のまま画面を離れたら止める

### 既存仕様との差分（着手時のチェックリスト）

- [ ] `app.json` の `UIBackgroundModes`（ストアの審査で用途の説明が要る）
- [ ] 解答画面と結果画面で再生の挙動を分ける
