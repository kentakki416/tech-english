## 着手トリガー

| 機能 | トリガー |
| --- | --- |
| 日ごと・問題ごとの集計表 | 直近 7 日・30 日の API が 1 秒を超えるようになった、または全期間（今でも 1 万人規模で約 2 秒）の遅さが気になるようになった |
| 期間の自由な指定・CSV の書き出し | 月ごとの報告など、決まった期間の数字を外に出す必要が出た |
| 継続率 | 登録した人がどれだけ使い続けているかを、施策の効果として見たくなった |
| ソースごと・難易度ごとの集計 | どのソースを増やすか・難易度の配分をどうするかを数字で決めたくなった |
| 行動イベントを使う分析 | 本番で ClickHouse と worker を有効にし（[minimal-deploy](../minimal-deploy/README.md)）、学習のイベントを送るようになった |

## 対象範囲

| | MVP | 着手後 |
| --- | --- | --- |
| 集計の方法 | 画面を開くたびに元のテーブルから集計 | 確定した日の分は集計表から読み、今日の分だけ元のテーブルから集計 |
| 期間 | 直近 7 日・30 日・全期間 | 開始日と終了日を選ぶ |
| 書き出し | ❌ | 問題ごとの成績を CSV で |
| 継続率 | ❌ | 登録した週ごとの、1〜8 週後に学習した割合の表 |
| 切り口 | 全体・問題ごと | ソースごと・難易度ごと |
| データの置き場所 | Postgres | Postgres と ClickHouse |

## 日ごと・問題ごとの集計表

- `daily_stats`（日本時間の日付ごとの学習したユーザー数・解いた回数・新規登録数など）と、`daily_passage_stats`（日付 × 問題ごとの解いた回数・正解の数・設問の数・時間の合計・アシストを使った回数）を作る
- 解いた人数・学習したユーザー数は日をまたいで足せない（同じ人を 2 回数える）ので、期間の値は元のテーブルから数えるか、HyperLogLog などの近似にする。どちらにするかは着手時に決める
- cron に日本時間の 0 時過ぎに前日の分を作るタスクを足す。退会で元の記録が消えても集計表の数は残る（今は退会で過去の数字も減る）ので、その違いを画面に書く

## 期間の自由な指定・CSV の書き出し

- `period` に加えて `from` / `to`（日本時間の日付）を受け取る。全期間と同じく、長い期間は週ごと・月ごとに束ねる
- CSV は admin の Route Handler で API の結果を変換して返す（API はこれまでどおり JSON）

## 継続率

- 登録した週（日本時間の月曜始まり）ごとに、1〜8 週後のそれぞれの週に学習したユーザーの割合を表にする
- 学習の条件はダッシュボードと同じ（問題を解いた・単語帳で答えた）

## ソースごと・難易度ごとの集計

- 問題ごとの成績を `sources`・`passages.difficulty` で束ねた表を足す
- 難易度ごとの正答率・時間超過の割合を見て、制限時間の式（[question-generation](../question-generation/README.md)）を直す材料にする

## 行動イベントを使う分析

- 途中でやめた問題（開始したが提出しなかった割合と、やめた位置）、画面ごとの閲覧数など、Postgres に痕跡が残らない数字は [user-behavior-events](../user-behavior-events/README.md) のイベントから出す
- admin は ClickHouse を直接読まず、api に ClickHouse を読む Repository を足して API で返す（admin は DB を触らない方針のまま）

## 既存仕様との差分（着手時のチェックリスト）

- [ ] 集計表を作るなら、`packages/db` にテーブル、`apps/cron` にタスクを足し、cron のスケジュール（EventBridge）にも載せる
- [ ] 集計表を読むようにしたら、README の「集計の方法」「数に入らないもの」（退会の扱い）を書き直す
- [ ] `period` を広げるなら `packages/schema/src/api-schema/admin/stats.ts` のスキーマと admin の期間の切り替えを直す
- [ ] ClickHouse を読むなら `packages/data-warehouse` に読み取りの口（今は `insertAll` だけ）を足し、ClickHouse が無い環境（minimal の既定）での振る舞い（その数字を出さない）を決める
